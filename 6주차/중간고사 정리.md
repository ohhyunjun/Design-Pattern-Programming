# 프로그래머의 기본능력

- 내가 생각하는 코드 설계 측면의 중요성은? 효율적인 문제해결과 유지보수성 향상 및 최적화가 필수적이여서
- **인스턴스**: 클래스로부터 생성된 객체

# 코드 품질 평가 방법

- **확장성**: 기존 코드를 살짝 수정 혹은 수정 없이 확장(extension)을 통해 새로운 기능을 추가하는 것
- **유연성**:
  - 확장을 위한 인터페이스가 준비되어 있어 기존 코드 수정 없이 새로운 코드 추가 가능 (확장성↑, 유연성↑)
  - 함수 구현 시 재사용 가능한 모듈과 클래스가 추상화된 형태로 이미 제공되어 이를 상속받아 씀 (재사용성↑, 유연성↑)
  - 클래스가 다양한 시나리오에 대응하고, 다양한 요구를 충족할 때 (사용성↑, 유연성↑)
- **유지보수성**: 기존 코드를 손상시키지 않고 새로운 버그 없이 빠르게 코드 수정과 추가 가능한 것
- **가독성**
- **간결성**: 가능한 단순하고, 명확하게
- **재사용성**: 반복 코드 최소화, 다형성, 단일 책임

# 객체 지향

- 소프트웨어를 객체 단위로 설계하고 개발하는 프로그래밍
- **객체**: 데이터와 메서드를 하나로 묶은 단위(물리적 사물, 논리적 개념, 모듈, 캡슐화, 정보은닉의 도구)
- **클래스**: 객체 생성을 위한 설계도, 고유이름, 속성, 잘 정의된 행위가짐(속성선언만 값은 안가짐)
  - **속성**: `private num : int = 10` (왼쪽부터: 가시성, 속성명(유일), 데이터타입, 초기값)
  - **행위**: 가시성 행위명 (매개변수) : 데이터타입

## 캡슐화 (Encapsulation)

- 데이터(변수)와 그 데이터를 처리하는 메서드를 하나의 클래스 안에 묶는 것
- 외부에서는 꼭 필요한 정보만 공개하고, 나머지는 숨기는 방법
- 추상화의 단위이고 재사용의 단위이며 정보 은닉을 실현한다
  - **정보 은닉**: 캡슐 내부 요소들의 세부 구현 사항을 외부로부터 숨기는 것
    - **이점**: 추상화 향상, 내부 알고리즘 변경 용이, 모듈독립성↑(다른 모듈과의 의존도 낮춰지기에), 확장성 ↑

## 공개 인터페이스 (Public Interface)

- 해당 객체가 다른 객체들에게 자신이 어떤 기능을 제공할 수 있는지를 선언
- 구현 세부사항(알고리즘 등)은 노출 금지✘, 함수명·반환 타입·매개변수만 제공

## 접근 제어자

- `public` = +
- `protected` = # (같은 패키지 클래스, 상속받은 클래스)
- `private` = -
- `package` = ~

## 다형성 (Polymorphism)

- 재사용성↑, 일관된 인터페이스 제공, 모듈화↑
- 슈퍼클래스를 추상 클래스나 인터페이스로 정의하고, 서브클래스가 이를 상속하거나 구현하도록 함으로써, 서브클래스가 슈퍼클래스에 직접 종속되지 않도록 함

### 오버로딩 (Overloading)

- **연산자 오버로딩**: 특정 연산자가 상황에 따라 다른 의미나 용도로 사용됨
- **함수 오버로딩**: 동일한 이름의 메서드가 매개변수에 따라 다르게 동작함
  - 한 클래스 내에서 함수 이름은 같고 매개변수가 다른 경우
  - 상속 구조에서 부모 클래스가 추상 클래스인 경우

### 오버라이딩 (Overriding)

- 상속 관계에서 발생, 메서드 이름과 매개변수는 동일하지만 구현 내용이 다름
- 예: `Shape square = new Square();`와 같이 자식 객체를 부모 타입으로 참조
  - 자식 클래스만의 메서드는 사용 불가, 사용하려면 형변환 필요

## 상속 (Inheritance)

- 클래스가 가진 행위를 재사용하기 위한 장치로, 클래스의 멤버를 다른 클래스에 계승시키는 것 (is-a 관계)
- **특성**:
  - 데이터 중복 제거
  - 데이터와 함수 추가 용이
  - 새로운 클래스 추가 용이
  - 다중 상속 가능 (일부 언어에서), but 동일 이름의 멤버로 인한 충돌 가능성 있음
    - 해결 방안: 하나는 상속, 하나는 참조로 다중 상속 받기

## 추상 클래스 (Abstract Class)

- 서로 다른 유형의 클래스들 간에 공통된 행위를 추출하여 정의한 가상의 클래스
- 상속 가능, 최소 하나 이상의 추상 메서드(가상 함수) 포함, 인스턴스 생성 불가
- 단일 인터페이스 제공: 자식 클래스들이 동일한 메서드 이름과 구조를 따름
- **특성**: 재사용성↑, 서브클래스가 대체 가능, 유지보수성↑, 확장성↑

## 인터페이스 (Interface)

- 특정 기능을 수행하기 위해 선언된 메서드들의 집합
- **특성**:
  - 구현 없음 (메서드 시그니처만 선언)
  - 객체 생성 불가
  - 다중 상속 가능
  - 모든 멤버는 public
  - 변수 포함 불가 (변수가 있으면 추상 클래스)

## 객체 관계

1. **상속 관계 (is-a)**
2. **복합 관계 (Composition, has-a)**
   - 복합 객체에 포함된 부분 객체들은 전체 객체에 종속적임
3. **연관 관계**
   - 한 클래스가 다른 클래스의 기능을 사용할 때, 관계가 지속됨
   - 전역 변수에 객체가 보관되어 클래스 생명주기까지 유지 (집합 관계와 유사, `new` 없음)
4. **의존 관계 (Dependency)**
   - 일시적 관계, 메서드 호출 시 사용, 메서드 종료 시 사라짐 (합성 관계, `new` 있음)
